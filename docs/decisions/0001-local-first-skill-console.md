# ADR-001: 以本地 Skill 启动同源面试工作台

## 状态

已接受

## 日期

2026-09-10

## 背景

项目原先可以直接打开 `frontend/index.html`，但 `file://` 页面无法正常调用 FastAPI，也不能安全地完成文档解析、本地配置和面试会话。目标用户希望安装后只需让 Agent “启动面试工作台”，然后在本地网页完成首次配置、文件导入和训练。

约束是桌面端优先、不引入账号或云同步，个人信息与原文件尽可能留在本机，仅模型推理使用用户自行配置的远程 API。

## 决策

- 将应用打包为可编辑安装的 Python 项目，提供 `interview-sim web` CLI，并在 `.agents/skills/interview-sim/` 放置仓库级 Skill。
- CLI 固定绑定 `127.0.0.1`，首选端口被占用时自动选择后续可用端口，并输出实际 URL。
- FastAPI 同时提供静态页面和 `/api/*` 接口，不开放宽松 CORS，并只接受本地主机名；用户不再直接打开 HTML 文件。
- 个性化配置和 session 与代码分离，保存在 `~/.interview-sim/`；目录权限为 `0700`，含密钥或面试内容的文件为 `0600`。
- 设置 API 对 API Key 只写不读：响应仅返回 `has_api_key`，空 Key 表示保留已有值。
- 文档上传仅用于本地文字提取，原文件不持久化；对文件大小、类型、DOCX 解压比、PDF 页数和图片像素设置上限。

## 替代方案

### 继续使用 `file://` 静态页面

优点是启动零依赖；缺点是服务端功能不可用，且容易让用户误判为产品已可运行。拒绝。

### 桌面壳（Electron/Tauri）

优点是能做成独立应用；缺点是引入新构建链、安装包、签名和更大维护成本，对当前“Agent 启动本地页面”的目标并非必需。暂不采用。

### 将配置和文档发给 Agent 处理

优点是实现简单；缺点是 API Key 可能进入对话历史，且文档处理的隐私边界不清晰。拒绝。

## 结果

- 用户需要先安装 Python 依赖，服务进程也必须在使用期间保持运行。
- 只绑定回环地址降低了局域网暴露面，但这不等于远程模型调用是本地的；用户开始面试后，提取文字、回答与语音仍会发往配置的 API。
- 原文件不落盘，但提取后的 JD、简历和回答会作为 session 内容保存，便于训练记录与证据报告。
- 日后若需局域网共享、多用户或公网托管服务，必须另行设计身份验证、CSRF 防护、安装升级和密钥存储方案。公开分发源码不表示服务适合暴露到公网。
