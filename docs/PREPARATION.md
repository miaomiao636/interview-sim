# 岗位准备：简历版本与真实经历

本页说明当前主分支源码的岗位准备功能。使用同一个工作台和现有分析模型，不需要安装 WorkBuddy，也不需要给三个顾问分别购买或配置模型。

## 两个入口有什么区别

岗位卡上的“开始面试”直接打开面试配置，选择简历版本、面试官、声音与难度。“准备这个岗位”先进入材料工作区，可以检查简历和岗位要求，再开始同一套实战面试。准备不是考试门槛，三个任务都可以单独运行。

| 任务 | 做什么 | 不代表什么 |
| --- | --- | --- |
| 简历诊断 | 对照岗位诊断内容，给出提升建议及可核对的原文改写 | 不是视觉排版检查、ATS 通过率或招聘概率 |
| 岗位要求分析 | 从 JD 提取要求，区分已有材料、待验证、缺少材料 | 简历提到某技能不等于已证明实际能力 |
| 整理练习素材 | 依据简历与已确认经历组织自我介绍和 STAR 提纲 | 提纲是草稿，缺失的行动和成果不会自动变成真实事实 |

打开页面、切换版本和保存本地正文不会调用 AI。点击上述任务才会向已配置的分析 API 发送本次岗位、简历和已确认素材，可能产生费用。

## 建议操作顺序

1. 创建或选择岗位，核对公司、JD 和原始简历。
2. 点击“准备这个岗位”，选择要检查的简历版本。
3. 运行需要的准备任务，查看原文引用与待补充项。
4. 对修改建议逐项核对职责、技能、贡献和数字，确认真实后采纳；每次采纳生成新版本，不覆盖原文。
5. 在简历编辑区补充自己能够核实的内容，保存为新版本。
6. 点击“开始面试”，在配置框中再次确认使用哪个版本。

同一诊断中互不冲突的建议可以连续采纳；重叠片段、已经改动的原文或其他版本分支会提示冲突。不能直接采纳的建议保留供参考，不会因为按了确认就自动放行。

## 内容建议与原文改写

诊断分为两层，不只纠正标点和措辞：

- **内容提升建议**：按优先级指出岗位匹配、个人贡献、成果证据、结构与内容取舍等问题，说明为什么、具体怎么做、需要补充什么，并附简历或 JD 原文。JD 引用只表示岗位要求，不表示候选人已经具备该经历。
- **可核对的改写**：只重组、精简已经提供的事实，保留原文对照并逐项确认采纳。没有必要改写时可以为空；缺失信息不会用猜测、占位符或虚构收益填进可采纳正文。

例如“参与工具开发”，应进一步核对本人负责的模块、交付物、验证方式和 AI 辅助边界，而不是只改标点，也不能直接改成“独立开发并提效 50%”。没有真实数字时可以补充可核实的定性结果，不必编造量化指标。

建议默认折叠，只显示标题、优先级、类型与状态；点标题或用键盘 Enter 展开，分组支持“展开全部 / 收起全部”。评分依据、待补充项、岗位要求、经历素材、练习提纲和历史结果也可折叠。在同一页面的同一岗位/版本刷新档案或轮询时，会保留主要分组和建议的展开状态；浏览器重新加载后默认收起，未保存编辑仍须先保存。

原文定位只允许恢复**唯一对应的空格或换行差异**，采纳时仍用真实原文片段，不做语义模糊替换。原文不同、位置不唯一或包含无来源新数字时继续阻止直接采纳。

旧诊断原样保留在历史中。更新到内容顾问规则后，请主动点击“简历诊断”生成新结果（会调用分析 API）；浏览、升级或刷新不会自动重跑，其他两类准备任务不会仅因本次简历规则更新而重跑。结构与引用校验不能保证所有模型的建议质量，仍需本人核对。

## 版本与评分

每个版本保存完整正文。切回旧版本可以比较原文或用旧版本面试；不会修改已保存的历史会话。面试实际使用的公司、JD、正文和版本由服务端读取并保存快照，不信任页面临时拼出的正文。

简历分数只属于接受诊断的那个版本。采纳建议后，新版本显示“未评估”，需要自行重新诊断；不会自动复制旧分或消耗一次模型调用。四个维度为内容清晰、结构组织、岗位针对性、贡献证据，各占 25%，总分由程序计算。

岗位材料、已确认经历或分析模型改变后，原准备结果保留在历史中并标明过期。过期建议不能直接采纳。更改岗位后，先保存当前岗位快照为新版本，再重新运行需要的任务。

## 真实经历素材

素材分为待确认、已确认、已拒绝和已由修订替代。只有明确确认的当前有效素材会被后续准备任务使用。修订已确认内容时，修改稿重新进入待确认，不能直接继承“已确认”。确认是使用者认可自己的描述，不是第三方背景核验。

查看来源中的会话、题号、作答轮次和原文引用后，再决定确认、修改或拒绝。模型写出的示范答案和理想提纲不能作为真实经历来源。不同岗位的素材不会自动混合。

面试结束后，选择提取本次面试素材，会启动可取消、可重试的分析任务（可能产生费用）。只从本次保存的原回答摘录，首次版本保留逐字引用，不让生成式概括直接充当事实；旧的未绑定岗位/版本会话不能按岗位名猜归属自动导入。

任务完成后进入该岗位准备页：先核对原文，再逐项确认、编辑或拒绝。重复提取同一来源不会重复增加事实。确认素材本身不会改简历，也不会重新评分或自动开始下一场；在编辑区保存新简历版本后，下一次配置明确选择该版本。

## 失败、取消与恢复

- 一个任务失败不会抹掉其他任务的成果。页面会显示当前阶段和错误，可主动重试。
- 同一输入重复点击不会重复启动相同的进行中任务；取消不会保证已经发送给提供商的请求免费。
- 重启服务后，未完成任务标为中断，不会偷偷重跑。输入已经变化时应新建任务，不复用旧输入。
- 保存冲突时先保留草稿，再刷新核对；“保存成功但暂时无法刷新”表示写入可能已经完成，请点刷新，不要重复保存。
- 离开准备页前会提醒未保存修改。重要正文应先保存，浏览器刷新或强制关闭不能保证保留内存草稿。

## 本地数据与使用边界

准备档案保存在数据根目录下的 `preparations/<preset_id>.json`，包含版本、任务输入和结果、修改历史及素材来源。默认数据根目录为 `~/.interview-sim/`，可用 `INTERVIEW_SIM_HOME` 更换。不要把这个目录放进公开仓库或作为排错附件上传。

本地 JSON 使用原子替换和单进程内锁，不支持多个服务进程同时写同一数据目录。仍沿用 Python、本地浏览器和通用 Skill 启动方式，未增加操作系统专属依赖。跨平台和真实语音设备的验证边界见 [兼容性说明](COMPATIBILITY.md)。
