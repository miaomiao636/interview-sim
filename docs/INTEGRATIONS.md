# 与本地岗位工作台联通

Interview Sim 可以接收兼容工作台通过浏览器发送的**单个岗位草稿**。这是可选功能：不安装 BossHunter 也能独立使用，不会接管投递、账号、聊天或招聘流程。

## 使用方式

1. 分别安装并启动 Interview Sim 与来源工作台。按 [快速开始](QUICKSTART.md)启动面试系统；使用终端打印的实际地址，端口可能自动顺延。
2. 在支持此协议的来源工作台中配置 Interview Sim 的根地址，例如 `http://127.0.0.1:8800`。只填写你自己启动并信任的本地服务；不要填写 GitHub Pages、公网地址或不明本地程序。
3. 从岗位详情点击“准备面试”，核对资料并勾选同意后，点击“打开并交接岗位”。新窗口接收后，显示“导入岗位 · 未保存草稿”。
4. 核对公司、岗位、完整 JD，按需要整理职责与要求，**自行填写或导入简历**，再保存岗位。选择保存的岗位后，可配置本次面试官、声音与难度。

导入阶段不会保存岗位或调用 AI。薪资原文保留在“公司背景”中的“薪资原文（来源岗位）”标记下，不猜测数值；可自行核对并填写薪资字段。原 JD 完整放入职责和原始 JD 栏，导入不代表系统已自动识别职责分类。关闭草稿即可取消；刷新或关闭窗口不会保留未保存草稿。

如果浏览器阻止新窗口、来源页已关闭、握手超时、资料过长或版本不支持，使用来源工作台的 **JD Markdown 导出**，再在面试系统中“创建岗位 → 导入 JD 文件”。导出方式也适用于尚无联通入口的 v1.5.0。网页兼容入口是否可用，以来源项目实际合并/发布的版本为准；不代表来源维护者已接受或背书本项目。

BossHunter 的可选入口尚在[上游功能讨论 #216](https://github.com/shengjidaguai-china/BossHunter/issues/216)阶段。测试者应使用双方关联 PR 的分支；普通用户可继续采用 Markdown 方式，不必等待上游合并。

## 协议 v1（供其他 Agent / 工作台实现）

只使用浏览器 `postMessage`，**不增加 HTTP 导入接口，不修改 CORS，不由后端请求另一服务**。

来源窗口必须由用户点击打开新的目标窗口，根 URL 为：

```text
http://127.0.0.1:8800/?import=job&source=http%3A%2F%2F127.0.0.1%3A8686
```

`source` 是来源页的精确 `location.origin`，不是岗位地址。双方 origin 必须为 `http://127.0.0.1:<port>` 或 `http://localhost:<port>`，有显式的 1–65535 非默认端口（80 不支持），不能带路径、尾斜杠、凭据、查询或片段；两方 origin 不能相同。不接受别名 IP、IPv6、公网或 HTTPS 来源。来源必须先验证配置地址，不应扫描端口、跟随重定向或自动启动未知程序。

握手：

1. 接收端验证入口与 `window.opener`，立即从地址栏清理 `import`、`source`，随后向来源 origin 发送 `{ "type": "interview-sim:ready", "version": 1 }`。
2. 来源同时校验 `event.origin === targetOrigin`、`event.source === openedWindow` 和 ready 的类型/版本，然后用精确 `targetOrigin` 发送下列 payload；禁止 `"*"`。
3. 接收端同时校验 origin 与 opener、字段白名单和长度，仅接收一次。成功打开未保存草稿后，回复 `{ "type": "interview-sim:received", "version": 1 }`，移除监听并清空 opener。这个确认**不表示已保存或已开始面试**。

```json
{
  "type": "interview-sim:job",
  "version": 1,
  "job": {
    "company": "示例公司",
    "target_role": "开发工程师",
    "city": "示例城市",
    "salary": "10-15K",
    "education": "本科",
    "jd": "负责开发工具并验证效果。"
  }
}
```

所有字段必须存在且是字符串；未知字段、错误版本、空白 `target_role` / `jd` 均拒绝。其他字符串可为空。

| 字段 | 最大长度（JavaScript UTF-16 code units） |
|---|---:|
| `company`、`target_role` | 160 |
| `city`、`education` | 80 |
| `salary` | 100 |
| `jd` | 15,000 |

超过上限应提示导出 Markdown，不能截断后冒充完整资料。JD 长度比普通原始文件导入更小，是为了兼容现有 15,000 字职责输入框。

接收窗口仅在明确的 `import=job` 入口监听，最多 30 秒；建议来源最多等待 15 秒，并在确认、失败、超时和离开页面时清理监听。普通访问不接收外部消息。接收时若已开始面试、正在操作、打开其他岗位弹窗或填入未保存的快速准备内容，会拒绝导入。显式导入优先于旧报告自动恢复，报告仍可从训练记录中查看。

## 数据与信任边界

- 仅传上方白名单中的岗位信息。**不传简历、API Key、模型设置、账号凭据、聊天记录、打招呼内容或面试记录**；不要从来源项目配置中读取这些内容拼入 JD。
- 岗位正文不进入 URL、URL hash 或本地存储；同一浏览器的两个窗口间传递，未保存草稿仅存在目标窗口内存和表单中。
- 为建立握手，来源窗口不能设置 `noopener` / `noreferrer`，因此只应打开用户明确信任的本地服务。接收端在完成、失败、超时或离开页面时主动断开 opener；该机制不是对本机恶意程序的隔离沙箱。
- 接收端将文本作为表单值，不执行 HTML 或其中的指令。协议拒绝多余字段；不要向第三方转发原始 payload。
- 用户后续点击 AI 识别、开始面试或生成报告时，仍按 [配置指南](CONFIGURATION.md)使用其自行配置的模型服务；这些操作与导入是分开的。

## 验证

`node --test tests/test_job_handoff.cjs` 覆盖来源、窗口、字段、长度、重复消息、忙碌拒收与超时清理。`python -m tests.run_browser` 包含两个不同本地 origin 的真实浏览器交接，核对空简历、完整 JD、安全文本呈现、显式保存与旧报告不抢页面；所有资料和模型调用均为测试替身。
